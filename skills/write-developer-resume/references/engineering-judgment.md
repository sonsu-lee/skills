# 엔지니어링 판단 표현

AI 보조 개발, 기술 선택 또는 포트폴리오 서술이 포함될 때 이 문서를 읽는다. 기술을 많이 썼다는 인상보다 상황에 맞는 결과를 선택하고 검증한 능력을 사실로 보여 준다.

## 판단 체인

입력에 존재하는 단계만 사용해 다음 체인을 복원한다.

```text
문제와 제약
→ 실제로 검토한 대안
→ 비교 기준과 trade-off
→ 선택과 지원자의 책임 범위
→ 검증·관찰·운영 gate
→ 결과와 남은 한계
→ 다음에 달라질 조건 또는 회고
```

모든 프로젝트가 전체 체인을 가질 필요는 없다. 누락된 단계를 그럴듯하게 만들지 말고, 중요한 빈칸만 확인 질문으로 남긴다.

## 기술 선택

`Next.js 사용`, `LiveKit 도입`, `ORM 적용` 같은 도구명은 시작점이다. 입력에서 확인되면 다음을 드러낸다.

- 해결하려던 문제가 무엇이었는가
- 다른 현실적인 선택지는 무엇이었는가
- 성능, SEO, 비용, 배포, 유지보수, 팀 역량, 운영 복잡도 중 어떤 기준을 실제로 사용했는가
- 선택하지 않은 대안의 장점과 포기한 것은 무엇인가
- 어떤 조건이 바뀌면 결정을 재검토할 것인가

검토만 하고 채택하지 않은 기술을 사용했다고 쓰지 않는다. 프레임워크 이름을 아는 것과 적합성을 판단한 경험을 구분한다.

```text
약함: Next.js를 사용해 웹 서비스를 개발했습니다.
강함: 내부 로그인 제품의 SSR·SEO 필요성과 배포 복잡도를 비교해 Vite SPA를 유지했습니다.
```

강한 예시는 해당 비교와 결정이 입력에 있을 때만 사용한다.

## AI 보조 개발

`AI를 사용했다` 또는 `AI로 빠르게 만들었다`는 사실만으로 강점이 되지 않는다. 다음 중 확인되는 내용을 연결한다.

1. AI에 맡긴 작업과 사람이 소유한 결정은 무엇인가?
2. 요구사항, 코드 품질, 성능, 보안, 운영과 유지보수 중 어떤 기준을 먼저 세웠는가?
3. AI 결과에서 어떤 결함·누락·부적합을 발견했는가?
4. 테스트, 리뷰, 비교 실험, 체크리스트 또는 관찰로 어떻게 검증했는가?
5. 결과를 어떻게 수정하거나 다시 유도했는가?
6. 제품 또는 팀의 품질 gate에 어떻게 연결했는가?
7. 실제로 확인된 결과와 아직 측정하지 않은 것은 무엇인가?

```text
약함: ChatGPT로 폼을 빠르게 구현했습니다.
강함: 생성된 폼 초안의 권한 누락과 오류 상태를 체크리스트·테스트로 찾아 제품 기준에 맞게 수정했습니다.
```

AI 도구명을 숨길 필요는 없지만 사람의 판단을 대신하게 두지 않는다. 입력에 없는 프롬프트 전략, 성능 개선, 자동화 범위 또는 팀 도입을 추가하지 않는다.

## 경력 단계별 AI 서술

### 신입·주니어

- 같은 기능을 여러 방식으로 비교한 경험
- 라이브러리 사용과 직접 구현의 차이를 탐구한 경험
- AI 코드의 문제를 분석하고 내부 원리나 한계를 학습한 경험
- 성능·유지보수성·확장성 기준으로 회고한 경험

작은 실험도 구체적인 질문, 비교와 배운 점이 있으면 사고의 밀도 근거가 된다. 운영 규모를 과장하지 않는다.

### 경력직

- 반복 작업 자동화와 사람이 검토할 경계
- 테스트, 리뷰, 배포, 모니터링 gate에 AI 결과를 연결한 방식
- 아키텍처와 인터페이스 선택 기준
- AI 도입 뒤에도 코드 품질과 운영 책임을 유지한 팀 프로세스

개인 도구 사용을 조직 차원의 프로세스 개선으로 확대하지 않는다. 실제 책임, 채택 범위와 결과를 구분한다.

## 포트폴리오와 이력서의 역할

둘은 같은 핵심 주장을 공유하지만 깊이가 다르다.

| 이력서 | 포트폴리오 |
| --- | --- |
| 어떤 엔지니어인지 압축해 선언 | 그 주장을 검증할 과정을 확장 |
| 대표 문제·결정·결과를 짧게 연결 | 대안 비교, 실험, 코드·화면·자료와 실패를 제시 |
| 선택 기준의 결론을 보여 줌 | 기준을 어떻게 만들고 적용했는지 설명 |
| 면접에서 확인할 질문을 남김 | 회고와 다음 재검토 조건까지 보여 줌 |

포트폴리오가 이력서 문장을 그대로 반복하지 않게 한다. 반대로 포트폴리오만 읽어도 문제, 역할, 판단과 결과를 이해할 수 있어야 한다. 링크가 없어도 이력서의 핵심 주장은 성립해야 한다.

## 판단 해상도 검사

- 기술 이름을 지워도 문제와 선택 기준이 남는가?
- 선택한 대안과 실제로 사용한 기술을 혼동하지 않았는가?
- “빠르게”, “효율적으로”, “안정적으로”를 뒷받침하는 검증이 있는가?
- AI가 한 일과 지원자가 판단·검증한 일이 구분되는가?
- 측정하지 않은 성능·시간·품질 향상을 만들지 않았는가?
- 실패와 되돌림을 숨기기보다 다음 판단 기준으로 연결했는가?
- 공개할 수 없는 내부 세부를 일반화해도 엔지니어링 판단은 보존되는가?

답할 수 없는 부분은 문구를 부풀리지 말고 확인 질문 또는 포트폴리오 보강 후보로 남긴다.

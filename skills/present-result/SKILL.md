# 결과 전달

전문 작업의 정확한 결과를 사람이 적은 해석 비용으로 이해하게 한다. 이 스킬은 결과를 다시 판단하는 검토 단계가 아니라 의미를 보존하는 마지막 표현 단계다.

## 불변 규칙

- 대화의 최종 사용자 응답만 재구성한다. PRD, ADR, 코드, 설정, 티켓과 다른 원본 산출물을 수정하지 않는다.
- 상태, ID, 수치, 범위, 근거, 권한, 검증 결과와 미결정 사항을 유지한다.
- `blocked`를 `conditional`처럼 완화하거나 가정·추천을 확정 사실로 바꾸지 않는다.
- 중요한 위험, 실패, 부정적 결과와 다음 결정을 쉬운 표현이라는 이유로 숨기지 않는다.
- 입력에 없는 원인, 영향, 담당자, 결정, 일정과 다음 행동을 만들지 않는다.
- 사용자가 독자, 언어, 길이 또는 형식을 지정하면 그 조건을 우선한다. 지정하지 않으면 업무 맥락은 알지만 해당 스킬의 내부 규칙은 모르는 동료를 독자로 삼는다.

## 1. 의미를 고정한다

전문 결과에서 관련 있는 항목만 찾는다.

- 결론과 완료·중단 상태
- 확인된 사실과 실제로 내린 결정
- 가정, 충돌, 미확인과 미결정
- 사용자나 업무에 미치는 영향
- 입력에서 확인된 다음 행동
- 상태 코드, ID, 경로, 수치와 검증 결과

정확히 보존해야 하는 값과 부정 표현을 먼저 고정한다. 정보가 없는 항목을 채우지 않는다.

## 2. 쉬운 말로 재구성한다

- 결론을 먼저 말하고 내부 절차 설명은 필요한 경우에만 뒤에 둔다.
- 전문용어와 영문 상태 코드는 처음 등장할 때 실제 의미를 쉬운 말로 설명한다.
- “무엇이 부족하다”뿐 아니라 입력에서 확인된 현실적인 영향을 함께 설명한다.
- 다음 행동이 확인됐으면 누가 무엇을 하면 되는지 동사 중심으로 쓴다. 담당자가 없으면 만들지 않고 결정이 필요하다고만 말한다.
- 같은 뜻을 전문용어와 쉬운 말로 반복하지 않는다.
- 단순화하면 의미가 달라질 수 있는 용어는 그대로 두고 짧은 설명을 붙인다.

필요한 항목만 다음 순서로 사용한다.

1. 한 줄 결론
2. 현재 상황
3. 왜 중요한지
4. 다음 행동
5. 기술 상세

빈 섹션을 만들거나 모든 결과에 같은 틀을 강제하지 않는다. 짧은 결과는 한두 문단으로 끝내고, 상태 코드·ID·경로·검증 기록은 판단에 필요할 때 기술 상세로 둔다.

## 3. 의미 보존을 감사한다

최종 응답을 내기 전에 원래 결과와 대조한다.

- 결론, 상태와 범위가 같은가?
- 수치, ID, 경로와 고유 이름이 그대로인가?
- 가정, 미확인과 미결정이 확정 표현으로 바뀌지 않았는가?
- 중요한 blocker, 위험과 부정적 결과가 남아 있는가?
- 새 사실, 결정, 추천, 담당자나 일정이 추가되지 않았는가?
- 사용자가 다음에 할 일을 이해할 수 있는가?

한 항목이라도 의미가 달라졌으면 표현을 고친다. 안전하게 풀어 쓸 수 없으면 원래 용어와 값을 유지하고 그 의미만 설명한다.

완료 조건: 전문 결과의 사실과 판정은 그대로이고, 사용자가 결론·영향·다음 행동을 내부 용어를 해석하지 않고 이해할 수 있다.

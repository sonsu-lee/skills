# Architecture Decisions Evaluation Rubric

- 하나의 기술 decision scope, context, 제약과 비목표를 먼저 고정한다.
- 실제로 가능한 대안을 같은 판단 기준으로 비교한다.
- evidence, constraint, assumption과 judgment를 구분한다.
- 추천을 승인된 결정이나 과거 rationale로 기록하지 않는다.
- 기본 결과를 decision packet으로 제공하고 ADR 파일을 쓰지 않는다.
- 이미 준비된 결정 기록은 `to-adr`, 제품 선택은 `product-discovery`로 보낸다.
- 가짜 대안·근거·결정권자·승인 생성, 무단 ADR 변경과 조용한 충돌 해결은 즉시 실패다.
